# F101 实时演奏版与 mda-lv2 修改内容对比报告

日期：2026-10-25。范围：对两个本地目录进行源码、配置及现有记录比对，未修改程序，未运行构建、烧写或板上测试。

## 1. 主要结论

当前工程是**以 MDA EPiano 为音源、由 F101 合成并通过 Windows 电脑演奏和播放的验证原型**。相对于原版 mda-lv2，改动可分为三层：

1. **工程裁剪**：从完整 LV2 插件集合中保留电钢琴，去掉宿主插件封装和其他乐器、效果器。
2. **音源适配**：保留采样和主要发声算法，改为独立 C++ 类，调整循环处理、输出格式、增益和默认参数。
3. **验证链路**：新增 Zephyr 板端程序、USB 请求/响应协议、Windows 虚拟键盘和播放程序，以及 RAM 加载工具。

**它沿用了原版电钢琴的采样基础，但不能视为与原版默认声音、MIDI 行为及插件能力完全等价。** 当前演奏依赖电脑，还不是脱离电脑工作的完整乐器固件。

### “核心保持原样”的含义

[说明.md](说明.md) 中的“四个 MDA 核心文件保持原样”，对应 [core-import.json](core-import.json) 记录的 `D:\MIDI工具箱\Windows电钢琴\source\` 来源，**不是指与本次指定的 mda-lv2 相同**。

本次计算了当前四个核心文件的 SHA256，全部与导入清单相符；该 Windows 来源目录未在本次工作区中核验。当前核心还保留了 MicroMDAEPiano / Teensy 移植说明，因此不能把所有差异都归为这次 F101 移植新写的代码。

## 3. 整体结构变化

| 维度 | 原版 mda-lv2 | 当前 F101 实时演奏版 |
| --- | --- | --- |
| 用途 | 由 LV2 宿主加载的乐器和效果器集合 | 板端电钢琴合成能力与 USB 实时播放验证 |
| 音源运行位置 | 运行 LV2 宿主的电脑 | F101 板端 |
| 演奏输入 | LV2 Atom 序列中的 MIDI 事件 | Windows 鼠标、电脑键盘生成的音符状态快照 |
| 音频出口 | 向宿主提供左右声道浮点缓冲区 | 板端输出 16 位 PCM，经 USB 返回电脑，再由 WinMM 播放 |
| 构建 | Meson、C++11、LV2 依赖 | 板端 Zephyr/CMake/C++17；电脑端 Windows C++17 |
| 预设与控制 | 插件控制端口、参数元数据、EPiano 五个预设 | 单程序槽、固定初始化参数，无通用远程参数调节 |
| 插件兼容 | 有 LV2 入口、URI、TTL 和预设描述 | 当前没有 LV2 插件入口，不能直接作为原 LV2 插件安装 |
| 运行依赖 | LV2 宿主和其音频/MIDI 系统 | F101、USB CDC 连接、Windows 程序及电脑音频设备 |

原版构建的 36 个插件中包含 EPiano、Piano、DX10、JX10 和多种效果器；这些其余能力没有纳入当前工程。原版 `src/` 实际有 37 份 `mda*.cpp`，其中 Looplex 未列入插件构建列表，不能把源码文件数直接当插件数。

当前链路为：

```text
Windows 虚拟键盘
  → 128 音符状态快照 + 延音/复位标志
  → USB CDC 请求
  → F101 对比状态、触发音符、合成 441 帧
  → USB 返回立体声 PCM
  → Windows 四块缓冲播放
```

依据：[原版构建列表](../../../mda-lv2-main/mda.lv2/meson.build)、[板端入口](src/main.cpp)、[电脑端入口](pc/main_pc_mda.cpp)、[当前 CMake](CMakeLists.txt)。

## 4. 音源核心保留了什么

### 4.1 采样数据相同

两份 `mdaEPianoData.h` 的文件字节和排版不同，但提取数组中的整数后，**422,418 个采样值逐点一致**，按 16 位存储计算为 844,836 字节。当前没有更换另一套电钢琴采样。

数组数值按逗号连接后的 SHA256，两边均为：

```text
42c943a6f684970c4fb64558ac6b07a0aa5bf73a9cd2f4aa6dc8c1e4e7129bed
```

这里的实际数组元素数与两版代码中沿用的 `WAVELEN = 422414` 宏是两个口径；本次比较的是完整数组数值，没有依据该宏截取数据。

当前头文件更大主要来自排版和移植包装，不能把文本 diff 的大量增删行解读成采样内容被重做。

### 4.2 采样映射和主要算法保留

逐项提取并比较 `kgrp` 的 `root/high/pos/end/loop` 赋值，两边 **121 项赋值全部一致**。这意味着键区划分、采样起止点和循环长度没有改变。

以下主要机制也继续保留：

- 根据音高选择键区，根据力度阈值 48、80 选择弱、中、强采样层。
- 通过 16.16 定点相位和线性插值改变采样播放速度。
- 使用指数包络处理自然衰减与松键释放，满复音时窃取较安静声部。
- 保留高频塑形、立体声展开、颤音/自动声像、失谐和二次非线性过载。
- 当前声部容量仍为 32；原版上限也是 32，不能将其描述为新增了 32 复音能力。

依据：[原版核心](../../../mda-lv2-main/src/mdaEPiano.cpp)、[当前核心](core/mdaEPiano.cpp)。

## 5. 音源核心的实质修改

| 修改 | 原版实现 | 当前实现与影响 |
| --- | --- | --- |
| 类与接口 | `mdaEPiano` 继承 `AudioEffectX`，依赖 LV2 事件 | 独立 `mdaEPiano` 类，公开 `noteOn()`、参数 setter 和 `process()`，方便嵌入固件 |
| 音频格式 | `processReplacing()` 输出左右声道 `float` | `process(right, left, frames)` 输出 `int16_t`，含量化及削波；调用顺序是先右后左 |
| 循环交叉淡化 | 构造时对 `k < 28` 的采样段原地修改数组 | 采样表改为 `const int16_t`，渲染时对循环尾部最后 50 点计算混合，避免预先改写或额外复制采样表 |
| 循环覆盖范围 | 初始化处理仅覆盖前述循环段 | 按实际发声声部执行，最高几个采样段也会进入该处理；循环附近不能直接假定逐点等价 |
| 插值计算 | 相位与采样差值使用 32 位整数乘法 | 乘法中间值改为 `int64_t`，扩大数值容纳范围 |
| 位置处理 | 超过循环尾部时执行一次回绕 | 改为 `while` 回绕，并增加数组位置范围保护 |
| 输出增益 | 初始 `volume = 0.2`，直接输出浮点混音 | 板端设 `setLoudness(1.0)` 得到内部增益 `0.16`，渲染末尾再乘 `0.5`，限幅到 ±1 后量化；增益链已改变 |
| 采样率 | 宿主通过 `setSampleRate()` 提供 | 当前配置固定为 44,100 Hz，未提供相同的动态采样率接口 |
| 预设 | Default、Bright、Mellow、Autopan、Tremolo 五个程序 | `NPROGS` 从 5 改为 1，不再保留原有程序切换、命名和复制接口 |
| 复音控制 | 参数 8 通过 `1 + int(31.9 × value)` 映射 | 改用整数 `setMaxPolyphony()`；板端初始化为 32，参数索引 8 不再按原方式驱动复音 |
| 事件时刻 | 按 LV2 事件的帧偏移，在音频块内部处理 | 当前固件在渲染整块之前统一应用状态变化，没有块内事件时间戳 |
| LFO 起始相位 | 空闲时收到事件，特定调制模式下重置相位 | 对应事件分支已去掉，启用调制后起音行为可能不同 |

“主要参数公式保留”不代表没有修改 DSP。循环淡化位置与覆盖范围、增益、限幅和整数输出都属于实际音频路径变化；本次没有进行两版音频对听或波形等价测试。

### 5.1 默认音色参数调整

以下比较原版 `Default` 程序与当前板端初始化后的值：

| 参数 | 原版 Default | 当前 F101 |
| --- | --- | --- |
| Decay | 0.50 | 0.40 |
| Release | 0.50 | 0.30 |
| Hardness | 0.50 | 0.40 |
| Treble | 0.50 | 0.20 |
| Detune | 0.146 | 0.00 |

从参数公式推断，当前设置倾向于更短的衰减与释放、更低的高频、取消逐音符失谐；听感影响仍需对听确认。Pan/Tremolo 仍为 0.50，LFO Rate 0.65、Velocity Sense 0.25、Stereo 0.50、Tune 0.50、Overdrive 0.00 继续沿用。

电脑端 `RemoteEngine::setParameter()` 只接受少数固定值并直接返回，**没有把动态参数发送到板端**；`setVolume()` 也只接受 1.0。现有界面因此不能承担完整音色编辑。

### 5.2 MIDI 能力变化

原版直接解析 Note On、Note Off、CC 和 Program Change。当前核心改为函数调用，其中 CC 处理有增删：

- 保留调制轮 CC1、延音 CC64 和延音保持 CC66。
- 不再实现原版的 CC7 音量处理，改由 `setLoudness()` 设置内部增益。
- 新增明确的 CC120、121、123、126、127 分支，分别调用清声部、复位控制器、停止声部及单音/复音设置。
- 当前运行协议仅携带音符状态、延音和复位标志，没有传输通用 MIDI CC、通道或 Program Change。

这些是“核心可调用接口”与“现有演奏链路”两个不同层次。当前电脑程序未接入实际 MIDI 输入设备；普通演奏时鼠标和电脑键盘的力度固定为 70，未发挥原采样的完整力度表达能力。

## 6. 新增的板端、通信与电脑功能

### 6.1 Zephyr 板端程序

[src/main.cpp](src/main.cpp) 初始化电钢琴，逐个比较 128 个音符的当前与上一份力度值；变化时调用 `noteOn(note, velocity)`，力度 0 表示松键。每个有效请求生成 441 帧，即 44.1 kHz 下的 10 ms 音频。

它是**电脑请求驱动的合成循环**，当前没有板端 DAC/I2S 持续播放任务，也没有接入霍尔键盘扫描或正式键盘协议。

### 6.2 自定义 USB 协议

[src/protocol.h](src/protocol.h) 同时被板端和电脑端引用，避免两边分别维护消息布局。

| 消息 | 内容 | 长度 |
| --- | --- | --- |
| 请求 `MDRQ` | 序号、441 帧声明、延音、复位、128 音符力度、CRC32 | 144 字节 |
| 响应 `MDRS` | 回传序号、帧数、活动声部数、处理耗时、立体声 PCM、CRC32 | 1,784 字节 |

在理想的每秒 100 次请求下，应用层双向数据量合计为 192,800 字节/秒，其中 PCM 为 176,400 字节/秒；不含 USB 协议开销。这是依据消息尺寸计算的数值，未在本次测量吞吐。

[src/usb_transport.c](src/usb_transport.c) 基于 CherryUSB CDC ACM，配置 High Speed 支持，保留 Full Speed 描述符；电脑按 `VID_FFFF&PID_FFFF` 查找串口，要求只有一个匹配设备。这是原型专用传输，不是标准 USB MIDI 或 USB Audio 数据接口。

### 6.3 Windows 演奏与播放

[pc/main_pc_mda.cpp](pc/main_pc_mda.cpp) 新增中文 37 键虚拟键盘、鼠标演奏、13 个电脑键盘音符键、Z/X/C 音区切换和空格延音。37 键是界面可见范围，不等于电脑键盘直接映射了 37 个独立按键。

音频通过独立线程请求板端 PCM，再用 WinMM 默认播放设备输出；4 块缓冲，每块 441 帧，名义队列容量为 40 ms。**40 ms 是缓冲配置，既不是端到端延迟实测值，也不能据此承诺实际演奏延迟。**

[pc/RemoteEngine.h](pc/RemoteEngine.h) 实现 [AudioEngineInterface](pc/AudioEngineInterface.h)，电脑侧构建仅编译界面程序，不链接 `core/mdaEPiano.cpp`，因此实际合成设计上位于板端。该接口目前是原型抽象，不能据此认定已建立正式乐器卡片 API。

### 6.4 异常处理和加载工具

- 电脑端检查响应 CRC、序号和帧数；读写失败后结束播放并提示处理连接。
- 板端等待请求超时 100 ms 会停止声部并清空按键状态。由于合成由请求触发，该期间并不会持续向独立板载音频设备输出。
- 板端响应发送失败后进入永久等待循环；这种路径需要重新运行或加载固件，不能保证只重开电脑程序即可恢复。
- [tools/load-ram.ps1](tools/load-ram.ps1) 检查 FEL 设备、初始化 PSRAM、进行探测写入和程序读回校验，再请求从 `0x40000000` 执行。脚本中未见 Flash 写入命令，属于 RAM 验证流程。

## 8. 当前限制与后续收敛建议

| 关注点 | 当前事实及建议 |
| --- | --- |
| 快速重复触发 | 快照只保留每个音符最后状态；两次快照之间完成的短按，或同音同力度的松开再按下，可能丢失。若继续用于演奏输入，应评估带时间戳的事件队列 |
| 独立演奏 | 依赖电脑生成请求并播放；若推进整机，下一步应建立板端连续音频输出与实际键盘输入链路 |
| 参数编辑 | 核心有 setter，远程协议和界面尚未提供动态参数控制；音色编辑需补齐这两层 |
| 复现条件 | `build.sh`、`build.cmd` 和电脑编译脚本绑定原 Windows/WSL 的 D、F 盘路径及外部 SDK；当前 macOS 目录不能按原路径直接复现，SDK 和工具链精确版本待补充 |
| 测试可追溯性 | 保存原始日志、实际构建配置、二进制与源码对应关系后，才能进一步复核板测及性能结论 |
| 配置遗留 | `config.h` 仍有 Teensy、LCD、EEPROM、混响/合唱等宏；当前工程没有对应实现，不能根据宏推断这些功能已接入 |
| 注释一致性 | `update()` 上方“当前全部禁用”与实际执行公式不符；头文件对 CC 音量的说明也与缺少 CC7 分支不符。后续维护宜校正 |
| 默认块大小 | `AUDIO_BLOCK_SAMPLES` 为 256，但当前协议和调用显式使用 441；当前路径取后者，不能把 256 当实际传输块大小 |

文件许可说明方面，两版 EPiano 核心文件均含 GPL-3.0-or-later 文本，因此不能根据原版顶层通用介绍，将这里描述为本次“从 GPLv2 改成 GPLv3”。当前新增 USB 文件保留 Apache-2.0 标识；原版的 `LICENSES/`、`.reuse/` 未随当前目录保留。

对照现有 PRD，本目录可作为 **F101 运行电钢琴核心并经 USB 回传播放的局部技术验证资料**。它尚未覆盖脱离电脑演奏、霍尔键盘、板载音频、屏幕实体交互、EO-1、卡片管理与完整更新救援；这些缺口描述当前范围，不表示本轮原型必须一次实现全部 P0，也不据此认定 F101 已成为最终主控方案。
