# AI 协作约定

- 修改工程设计前，阅读[项目入口](README.md)、[系统架构](engineering/architecture.md)和直接相关的接口、局部 README、验证记录；涉及产品边界时核对[现有 PRD](运营与开发策略/PISCIS_1.0_PRD_2026-10-20.md)。
- 先检查当前 Git 状态及目标文件；保留用户未提交修改。部分子目录有独立 Git 仓库，修改前确认所属仓库，不自动合并、重建或提交全部工作区。
- 工程分支名称不等于当前基线。适用版本不明时标为 Open；用户已明确确定的技术方案不得擅自替换。
- 重要架构取舍在 [DECISIONS.md](DECISIONS.md)记录问题、决定、理由和来源；普通代码修改只更新直接相关内容，不生成成套文档。
- 实验实际执行后才能写成验证结果；计划、推测、既有报告摘录分别标明。Confirmed 必须有适用版本、条件和证据，局部检查不得描述成整机通过。
- 修改接口时检查直接调用方、电气/机械/时序约束及相关文档链接；规范或代码只维护一份权威定义，其他位置链接引用。
- 不把未确认假设写成正式规格；缺失参数简写“待补充”，不自行编造需求、选型、排期、测试值或完成状态。
- 优先更新已有文档；专题用于跨专业索引，不复制 BOM、针脚表、CAD、PCB 或报告全文。不自动重写整个知识库。
- 只在信息被复用、形成模块依赖、需要复现或原文已难维护时拆页；临时想法允许直接进入 [BACKLOG.md](BACKLOG.md)。
- 内部链接用相对路径；修改文档后检查目标存在、锚点有效、版本适用。保持普通 Markdown 阅读器可用。
- 不为本次文档任务运行会重建原理图/PCB 的生成器；工程验证前区分只读检查与写入脚本。
- 保持变更和提交范围与当前任务相关，避免无关重构、移动文件、批量格式化或整理既有生成物。
