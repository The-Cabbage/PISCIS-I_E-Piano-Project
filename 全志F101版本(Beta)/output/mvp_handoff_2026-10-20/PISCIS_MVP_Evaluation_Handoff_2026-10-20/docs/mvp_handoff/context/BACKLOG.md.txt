# 任务、问题与想法

[项目入口](README.md) · [关键决策](DECISIONS.md) · [验证记录](EXPERIMENTS.md)

以下是根据现有资料整理的**建议推进顺序**；未勾选不代表已经开始执行。Now 只保留当前少量工作，Next 是后继事项，Later 可直接接收未分类想法。每项只维护动作、完成边界和必要链接，参数与结果回到其权威文档。

## Now

- [ ] 明确本轮 MVP 验证切片、采用的键盘/主板/结构版本及通过条件；在[项目入口](README.md)更新摘要，在[架构](engineering/architecture.md)标明选用工程，不由目录名称推定当前基线。
- [ ] 收敛[霍尔键盘演奏链路](engineering/topics/keyboard-chain.md)的首轮验证条件：定位实物与样机版本，明确扫描互斥、建立时间和触发稳定性的测量方法，再执行 [E-002](EXPERIMENTS.md#e-002)。

## Next

- [ ] 明确键盘与选定主板之间的电气连接及事件协议，在直接使用该接口的工程中维护一份规范，由[架构](engineering/architecture.md)引用；校准、错误处理及版本兼容需有明确边界。
- [ ] 在选定硬件上定义并验证 EP-1/EO-1 的最小发声与交互链路；指标及验收口径沿用 [PRD 第 7、12 节](运营与开发策略/PISCIS_1.0_PRD_2026-10-20.md)，结果写入[实验记录](EXPERIMENTS.md)，不以浏览器原型代替目标硬件测试。
- [ ] 找回 PRD 所述双拇指初步实物测试的原始记录；若无法找到，标清仅有文档陈述，并安排可复现的握持与演奏验证。
- [ ] 按[市场资料索引](市场调查资料/README.md)选择一个近期必须验证的用户或商业假设，先写验证目标与方法，再收集证据；需要时回写 PRD，避免重做全部调研。

## Later

- [ ] 在 USB 与存储方案明确后，细化卡片安装、固件更新、救援及校准保护的验证切片，沿用 [PRD 第 8、10 节](运营与开发策略/PISCIS_1.0_PRD_2026-10-20.md)。
- [ ] 首代演奏体验成立后，再按 [PRD 第 4、11 节](运营与开发策略/PISCIS_1.0_PRD_2026-10-20.md)评估 SDK、插件 API 和社区扩展，不提前冻结生态接口。
