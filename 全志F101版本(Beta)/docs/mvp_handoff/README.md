## 2. 本轮目标及产品边界

### 2.1 用户给定的目的（本轮权威输入）

> PISCIS MVP 拓展板以 YuzukiNeko F101 开发板为核心，主要验证音频处理能力与极简交互方案的可行性。
>
> 音频部分：通过 I²S 接口连接 ES8388 Codec，实现立体声音频输出，配备 3.5mm 耳机接口，验证基础音源合成、实时 DSP 效果及多参数调节性能。
>
> 交互部分：使用 4Pin OLED 显示屏、五维摇杆及独立开发的 MT6701 磁编码转盘。通过摇杆选择参数、转盘进行无跳变的相对调节，验证单层菜单的操作流畅性与实时反馈。
>
> 开发目标：完成声音生成、参数编辑、屏幕反馈与耳机播放的完整闭环，评估 F101 的实时音频性能及交互体验。当前暂不集成霍尔键盘、电池管理、USB Host 扩展及完整乐器卡片系统。

上述方向记为 **Decided**，来源为 2026-10-20 本次用户说明。后续补充要求：**MT6701 和 OLED 的 Datasheet 不纳入本次收集**；这不取消它们在 MVP 中的功能职责。范围记录见 [D-MVP-001](../../DECISIONS.md)。

## 6. 硬件接手说明

### 6.1 目标链路与当前断点

```text
目标音频链路：测试音/音符事件 -> F101 音源 -> DSP -> I²S -> ES8388 -> 耳机输出外围 -> J5 -> 立体声耳机
目标控制链路：SW1 选中参数 + MT6701 转盘产生增量 -> 同一参数状态 -> OLED 显示 + 音频参数更新
目标控制总线：F101 -> Codec 控制口；OLED 与转盘各自的具体接口待补充
当前断点：外围实例已摆放，功能网络、供电、总线分配、耳机外围和固件均未完成
```

该图表达目标和责任，不是已实现的接口规格。

### 6.2 开发板插接与供电

先核对实际开发板的硬件版本、丝印和源文件对应关系。母座方向以局部 README 为准：元件面朝上、USB-C 在上、TF 在下；不能把右侧源 H2.1 误当右上角。

两排圆孔中心距是源文件测得的 **17.926 mm**，两排起点还有 **0.010 mm** 的纵向偏移。不要为了网格好看改成常见排距；制板前需要实物核对、公针朝下安装方式和母座高度检查。开发板装配轮廓/圆圈在 `Dwgs.User`，不是自动生成的扩展板螺丝孔。

J1 只是按源板引出 `VBUS` 与 `VCC-3V3`，没有为扩展板增加稳压、隔离或防反灌。供电入口、各电源域、扩展负载电流、稳压余量和去耦/滤波方案待补充；本轮无电池管理不等于可以省去 Codec 所需电源外围。不要把 5V 或模块板上上拉电平直接视为 F101 GPIO 的允许输入电平。依据 F101 电气页及实际板卡电源连接核对。

### 6.3 I²S 与控制总线

ES8388 的数字音频口与寄存器控制口是两组不同接口：仅接 I²S 不足以完成 Codec 初始化。先确定 MCLK、BCLK、LRCK 的来源和主从关系，再核对两端的采样率、有效位宽、时隙宽度、声道顺序、对齐和时钟边沿。

**Proposed，仅供分配前检查：**F101 Datasheet 的 Port D 表列出 PD6/PD7/PD8/PD9 可在 Function4 下构成 I2S0 MCLK/BCLK/LRCK/DOUT0；当前母座已引出这些网络。该组尚未被分配或连入电路。尤其 PD8/PD9 也有 TWI1 功能，不能同时用于 I²S 与另一条硬件 I²C。最终控制总线、调试串口和外设 GPIO 选择需统一检查 BSP/pinmux、开发板已有占用及实际电平，随后在正式原理图或单一接口定义中维护。

如果本轮只输出音频，不据 Codec 的 ADC 能力自行扩展麦克风/录音功能；未用引脚按手册处理。候选控制口模式、片选/地址绑法及上拉网络待补充。寄存器地址和传输中的地址字节应区分，避免把 7 位地址与移位后的读写地址混用。

### 6.4 ES8388、电路外围与当前符号差异

本地 `PISCIS_Controls_Audio:ES8388` 对参考输出脚的 ERC 类型做过按手册核对；当前 U1 使用的是标准 `Audio:ES8388`，本次 ERC 仍把 10/19/20 脚当输入并报未驱动。接手时对照手册和本地库说明检查缓存符号，不通过批量添加电源标志来“清零”这些错误。是否改用本地实例属于后续工程修改，应先核对所有针号、封装和既有连接。

硬件设计重点：各电源/地与 EPAD、VMID/VREF 去耦、控制模式、输出路径、耦合及负载条件。手册典型应用的耳机/线路输出外围应结合实际负载审阅，不凭示意图省略元件。PCB 需检查电源去耦距离、时钟/数字回流与模拟输出的布局关系；具体元件值、铜区策略和走线约束待补充。

ES8388 有两套本地封装：KiCad 版 EP 为 2.6 mm，EasyEDA 版为 2.4 mm，且 1 脚朝向有差异；厂商裸露金属尺寸不等于推荐铜焊盘/钢网开口。不能只按“QFN28 4×4”替换。

### 6.5 3.5mm 耳机接口

当前 J5 是首韩 `PJ-327A-Y / C17701692`。原厂图纸保留 1～5 号与开关关系，库没有把未知 T/R/S 强行命名。必须用原厂图、实际插头接触关系或通断测量确认左右声道、回地与开关端，再接输出网络。不能把私有库中的 TRRS 或其他品牌同名座直接替代它。

已绑定的 HX 系列 3D 模型为参考件，和首韩图纸高度存在差异，不作为外壳净空或装配通过证据。连接器朝向、板边位置、插拔空间和受力需要结合结构确认。

### 6.6 五维开关、OLED 与转盘

- **SW1：**ALPS SKRHADE010，四方向加中央按压；端子对应、定位孔和固定焊脚说明以本地库 README 与目录图为准。上/下/左/右的软件映射在装配朝向确定后统一；GPIO 电平、公共端连接、上拉及消抖参数待补充。不能默认所有固定焊脚与公共端短接。
- **OLED：**用户要求为 4Pin 屏幕，具体模块、供电、接口协议、针序、地址和刷新能力待补充。J2 的 4 个焊盘尚未定义这些含义。模块是否自带上拉/电平处理需核对，不能只凭“4Pin”认定兼容。
- **MT6701 转盘：**用户说明为独立开发模块，本目录未定位到其电路、固件或机械源文件。对外输出方式、连接器针数/针序、工作电平、方向、安装磁铁与校准状态待补充。两个三针排母不构成接口定义；不因接头数量而改选接口。按用户补充，本轮不收集其 Datasheet。

| 责任 | 最小职责 | 开发约束 |

| 音频传输 | I²S 与 DMA/FIFO、缓冲交接、欠载统计 | 核对缓存一致性、对齐、DMA 可达内存及中断/任务边界 |

| 显示 | 参数名称、值、选中状态、必要错误状态 | 避免同步全屏刷新占用音频关键路径 |
| 测量 | 处理耗时、队列/缓冲状态、欠载、交互时延 | 输出版本及条件；日志不应改变被测链路的实时行为 |

音频关键路径避免不可控阻塞；显示、总线重试、日志和后续存储操作需考虑其最坏耗时。具体同步机制由目标环境决定，不预设某种锁、调度器或驱动 API 已可用。

对每块音频缓冲记录：采样率 `Fs`、每块帧数 `N`、通道数、有效位宽和总线槽位宽。块周期为 `Tblock = N / Fs`，应测量最坏处理耗时和调度延迟；仅平均值低于周期不足以说明无欠载。总延迟还包括输入采集、事件传递、缓冲排队、Codec 和模拟链路，不能直接把 `N/Fs` 写成整机延迟。

输出报告需要分别说明：最小播放链路、音源单独、音源加 DSP、同时快速操作/刷屏等条件；记载 CPU 时钟、内存使用、缓存/DMA配置、欠载与可听异常。本轮采样率、位宽、块大小、时长、负载及合格阈值均待补充。

## 8. 相对调节与单层菜单

### 8.1 交互不变量（来自用户目的与现有 PRD）

1. 摇杆改变当前选中参数；转盘以该参数的**当前值**为起点增减。
2. 切换参数后第一次转动，不把绝对角度或旧参数的数值写入新参数。
3. 单层界面可辨认参数名称、当前值和选中状态；声音、显示与参数状态对应。
4. 连续参数变化需要平滑；有界参数到边界后保持边界，环形或离散参数的规则需明确。

按压确认、返回、长按、连发、转盘加速和页面容纳的参数数量待补充，不自行增加复杂手势或多层菜单。

### 8.2 可供实现的处理流程（Proposed）

```text
采集控件 -> 校验/消抖 -> 得到动作或相对增量 -> 更新选中项/参数目标值
                                               -> 同步供显示读取
                                               -> 在音频边界消费并按参数特性平滑
```

如果转盘模块输出的是绝对角度，可对相邻有效采样做环绕差分，再转换为增量；第一帧/重连后只建立基准，不更新参数。若输出 AB 等增量信号，则按对应协议解码，不重复套用绝对角差分。模块实际接口未定，不能提前认定某条算法为正式驱动。

绝对角差分候选写法：`d = wrap(current - previous, -P/2, P/2)`，`P` 为该接口的一圈计数。该方法要求采样间位移不超过半圈，等于半圈时也存在方向歧义；需结合实际接口、采样周期和最高操作速度定义有效范围。异常读数、磁场异常、通信中断或丢采样后重新建立基准，避免把恢复时的跳差施加给参数。

事件应携带顺序/时间信息或在统一处理点消费，保证“选择参数”和“转动增量”的先后关系可解释；参数切换时清理或归属旧增量，避免排队事件误加给新参数。跨零、微动、往返、快速转动和反转均需验证。步进、死区、迟滞、加速、平滑时间及方向规则待补充，不能将示例值写成需求。
