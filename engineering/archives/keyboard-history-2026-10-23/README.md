## 文件布局

每个原目录下面分为 `project/`（工程提交）和 `kicad-local-history/`（KiCad 自动历史）：

- `index.csv`：提交编号、提交者及原始时间与时区、保存说明、父提交、分卷文件名、快照目录、文件数。可用文本编辑器或表格软件打开；索引按对象编号排列，按时间查找请使用 `committer` 列的 Unix 时间戳。
- `snapshots-*.zip`：约 64 MiB 分卷；每个提交的完整文件快照位于 `snapshots/<完整提交编号>/`，同一快照不会跨卷。每卷内的 `SHA256.json` 记录文件路径、SHA-256、原 Git blob 编号和文件模式。
- `summary.json`：源 HEAD、发现和导出数量、导出异常及各 ZIP 的 SHA-256。
- `source-fsck.txt`、`source-refs.txt`：保留源完整性检查及引用信息，失效引用不能据此恢复。

顶层 `loose-backups.zip` 另存 4 个未跟踪的 `.bak` 文件及 8 个 KiCad 历史说明/忽略配置文件，共 12 个文件；对应内容与校验见 `loose-backups-summary.json`。它们是归档时的文件内容，没有额外的历史版本。顶层 `summary.json` 汇总八套导出结果，`SHA256SUMS` 覆盖本归档所有其他文件。

## 不使用 Git 取回文件

1. 打开对应工程、对应历史类型的 `index.csv`，根据时间和保存说明选取记录。
2. 解压该行 `archive` 指定的 ZIP，进入 `folder` 指定目录，复制需要的文件到一个新的恢复目录。
3. KiCad 本地历史主要保存原理图和 PCB，不包含完整私有库及项目配置。需要打开旧设计时，先从适用工程快照取回配套文件，再在副本中放入所选历史快照。工程快照与自动历史之间没有已验证的一一对应关系。
4. 归档不能直接替代 KiCad“本地历史”菜单。请保留当前工程，避免直接覆盖；历史文件可能依赖对应版本的 KiCad 与库。

在本目录运行以下命令可复核归档文件是否改变，无需 Git（macOS）：

```sh
shasum -a 256 -c SHA256SUMS
```

导出脚本只读取源仓库，拒绝覆盖已有导出目录；再次导出请先为脚本配置新的输出目录。生成普通快照会保留大量重复文件，不等同于 Git 的增量存储；是否随新“霍尔键盘”仓库上传留待迁移时确定。
