## 1 产品定义

**PISCIS 是一款以演奏体验为核心的掌上数字乐器，通过精心设计的硬件交互与可替换的数字乐器卡片，在有限的体积内提供丰富、直观且富有个性的音乐体验。**

商业定位为具有精致工业设计、鲜明产品人格和低认知负担的消费级音乐硬件。产品价值以声音、演奏趣味、键盘手感、操作反馈与独立使用体验体现；功能数量和开放平台能力不作为主要卖点。

产品采用双手握持、双拇指演奏的形态，强调随时拿起、即刻演奏的自由感。围绕碎片化演奏、旋律即兴与声音探索，建立适合掌上设备的演奏方式。

首代以 EP-1 电钢琴和 EO-1 电风琴为核心，完成独立使用、声音编辑、乐器更换与可靠恢复的完整体验。普通用户无需理解内部硬件架构，也无需参与开发即可使用。

PISCIS 的目标是创造一件让人愿意随身携带、随时拿起并享受演奏的数字乐器。

## 2 用户与使用场景

核心用户是希望在日常生活中随手演奏的音乐爱好者，以及需要便携乐器进行旋律即兴和声音探索的创作者。开发者是后续扩展用户，开发需求不应增加普通用户的使用负担。

| 场景 | 用户需要 | 产品回应 |
| --- | --- | --- |
| 碎片时间演奏 | 拿起设备后尽快开始弹奏 | 独立发声，直接进入可演奏状态 |
| 旋律即兴 | 用双拇指自然地组织音符 | 围绕握持姿态设计琴键布局与响应 |
| 声音探索 | 边听边调整，理解声音变化 | 核心参数置于首层，转轮连续调节 |
| 更换乐器 | 少量选择即可获得不同体验 | 本机最多安装五张乐器卡片 |
| 长期使用 | 设备可检修，软件可恢复 | 可拆结构、校准保护与救援刷机 |

双拇指演奏已通过初步实物测试，验证了其趣味性。长期握持舒适度、键盘手感和连续演奏表现仍需进一步验证。

## 3 产品原则

**Instrument First，乐器优先。** 声音品质、键盘手感、演奏响应和独立使用体验决定首代是否成立。功能扩展服从这四项要求。

**交互围绕演奏展开。** 用户应能快速找到核心参数，并在调整后立即听到变化。界面与声音编辑不能妨碍基本演奏。

**主动限制选择空间。** 本机保留最多五张乐器卡片。电脑端负责管理，本机负责演奏。

**内部结构服务于检修和开发。** 主控、键盘、电源与音频需要便于测试和排障。拆分程度以实际收益为依据，不预设通用计算模块或跨代升级标准。

**官方交付可靠产品，社区保留再创作空间。** 首代建立清晰的接口和恢复路径，开发工具与生态服务分阶段完善。

| P0 | 核心硬件交互 | 2.8 英寸屏幕、阻尼转轮、五维摇杆与霍尔键盘 |
| P0 | 官方乐器 | EP-1、EO-1 及各自完整的声音与界面 |
| P0 | 乐器卡片管理 | 最多五张卡片，本机切换，电脑端安装与更换 |
| P0 | 固件更新与救援 | USB 更新、异常恢复、出厂校准数据保护 |
| P0 | 可检修结构 | 后盖可拆，关键部件可检修，键盘与主板可独立测试 |
| P0 | 基础接口文档 | 音频、按键、显示及键盘通信接口形成可用文档 |
| P1 | 开发者入门工具 | SDK、HAL、最简合成器示例及构建刷写说明 |

首代不纳入完整音乐工作站、复杂编曲系统、多卡片叠加演奏、官方计算模块升级业务及通用硬件模块生态。MIDI、录音和其他扩展功能需单独评估，未确认前不计入首发范围。

## 5 演奏与硬件交互

### 5.1 握持与键盘

整机采用双手握持、双拇指演奏。外壳支撑、琴键位置与重心需要共同设计，使用户在正常演奏时能够稳定握持，并减少误触。

键盘采用霍尔检测方案。琴键触发应稳定、可重复，按下与释放事件应完整对应。力度响应需要结合键程、机械结构和传感器数据验证，具体曲线在样机阶段确定。

琴键数量、音域、键程、触发位置和力度精度在样机阶段确定。

### 5.2 屏幕与实体控件

| 部件 | 已确定规格 | 交互职责 |
| --- | --- | --- |
| 屏幕 | 2.8 英寸，320 × 320，RGB | 显示当前乐器、核心参数、选中状态与必要系统状态 |
| 转轮 | 无限旋转，具有阻尼感 | 按相对增量调整当前参数 |
| 摇杆 | 五维输入 | 方向操作选择参数，中心按压用于确认或进入 |

转轮以参数当前值为起点进行增减。切换参数或卡片后，首次转动不得将数值跳到与转轮物理位置对应的值。

连续参数需要平滑变化；离散参数需要明确显示当前档位。有上下限的参数到达边界后保持边界值，环形参数的循环行为需由卡片明确定义。

参数选择、数值变化与声音反馈需要保持一致。快速转动时的步进、加速和阻尼手感，应通过样机验证后统一确定。

### 5.3 界面层级

当前乐器的核心音色参数集中于首层界面。用户能够直接看见参数名称、当前值和选中状态，并通过摇杆与转轮完成调整。

卡片可以拥有独立的参数布局和美术风格，但选择、确认、调节与返回的基本逻辑保持一致。个性化视觉不能降低文字可读性或增加基础操作成本。

乐器切换、总音量和必要的音域调整需要便于访问。具体入口、返回方式与快捷操作在交互原型中确定，不依赖未经验证的复杂手势。

### 5.4 独立使用与状态保存

日常演奏和本机已有卡片的切换无需连接电脑。开机后进入可演奏状态，不要求登录账号或联网。

官方固件需保存当前卡片与用户调整的必要状态。参数保存不得阻塞音频处理；断电后的数据一致性需要验证。恢复默认设置时，应保留设备校准数据。

独立使用所需的供电和音频输出方式必须在硬件冻结前确定。内置扬声器、音频接口、电池规格及续航当前仍属待定项。

## 6 Instrument Card 乐器卡片

### 6.1 卡片定义

**每张乐器卡片都是一件完整的数字乐器，包含独立音源、参数结构、交互布局与美术风格。**

卡片在产品层面作为整体安装和更换。它不等同于音色预设，也不要求用户插拔实体卡片。首代卡片的具体封装与加载方式由技术验证确定，不以完成通用插件运行时为前提。

| 组成 | 内容要求 |
| --- | --- |
| 音源 | 发声逻辑、所需资源及效果处理 |
| 参数 | 参数名称、范围、默认值、步进与映射关系 |
| 界面 | 首层参数布局、选中反馈与操作状态 |
| 美术 | 与乐器声音一致的视觉表达 |
| 管理信息 | 卡片标识、版本、兼容信息与资源需求 |

### 6.2 本机规则

本机同时安装最多五张卡片，EP-1 与 EO-1 占用其中两个名额。该限制指已安装乐器数量；卡片内部的参数和预设规模由资源预算决定。

首代按单张卡片演奏设计。切换卡片后，需要同步加载对应音源、参数状态与界面，并明确显示加载结果。切换过程应避免异常爆音和卡音；是否保留尾音及具体切换时长待性能验证。

卡片安装、替换和删除由电脑端工具完成。本机在没有可用卡片或遇到损坏卡片时，应给出明确提示，并提供恢复官方乐器的路径。

### 6.3 参数与兼容性

不同卡片可以拥有不同的参数结构，但参数选择和转轮调节遵循统一规则。每个核心参数都应产生可辨识的声音变化。

安装前需要检查卡片与设备固件的兼容性及可用存储空间。不兼容或不完整的卡片不得进入正常可演奏列表。卡片版本升级后的参数迁移规则在封装方案确定时一并定义。

## 7 首发官方乐器

### 7.1 EP-1 电钢琴

EP-1 提供具有鲜明个性的电钢琴体验。重点是音符起音、力度层次、延音与整体质感，以及双拇指演奏下的表达性。

首层参数围绕用户能够直接感知的声音变化组织。明亮度、驱动、颤音和空间感可作为候选方向，具体参数、数量和默认值在音源样机验证后冻结。

### 7.2 EO-1 电风琴

EO-1 提供具有鲜明个性的电风琴体验。重点是持续发声、音色层次、音符衔接与动态效果，并与 EP-1 形成清晰的声音差异。

音色构成、驱动、旋转扬声器效果和空间感可作为候选方向。具体引擎及控制方式待验证，首代不承诺完整复刻传统风琴的全部控制结构。

### 7.3 共同要求

两张卡片都需要提供开机即可演奏的默认声音，以及独立、清晰的视觉风格。默认值应适合直接使用，常用参数范围内应保持合理的响度和可控的声音变化。

音源实现方式由声音目标、性能和资源占用共同决定。首发验收覆盖单音、快速连奏、重复触发、多音及效果处理。

## 8 电脑端管理工具

电脑端工具负责卡片管理、官方固件更新及设备恢复。日常演奏不依赖电脑端运行。

首代需要完成以下操作：

- 识别通过 USB-C 连接的设备，显示固件版本、卡片列表和可用空间。
- 安装、替换与删除卡片，安装前提示兼容性及空间问题。
- 更新官方固件，显示进度、结果和失败后的处理方式。
- 引导用户进入救援模式，恢复官方固件及官方乐器。

卡片管理需要显示五张卡片的安装限制。达到上限后，用户应能明确选择替换对象；涉及删除或覆盖的操作需先确认。

传输失败或连接中断后，设备不得将未完成安装的卡片标记为可用。已有可用数据应保留，或能够通过恢复流程重新获得。

桌面应用或 Web 工具的形式、支持的操作系统及驱动依赖，在 USB 通信方案验证后确定。浏览器直接刷机不作为当前已确定能力。

## 9 内部架构与可维修性

### 9.1 主板与键盘解耦

首代优先采用主控与音频 PCB、独立霍尔键盘 PCB 的结构。电源是否继续拆板，由布局、噪声、装配和测试需求决定。

主控与音频 PCB 负责音源运行、音频处理、显示、系统管理及外部连接。F101、F133 仍为候选方案，具体主控、内存、存储和音频器件通过样机验证确定。

霍尔键盘 PCB 负责传感器采集、校准、触发判断及力度估算，通过稳定的数字协议向主板发送演奏事件。键盘应能够脱离音源主板进行独立测试。

键盘协议至少需要明确按键标识、按下与释放、力度信息、校准状态及异常处理。传感器原始数据和调试能力面向开发与检修，不进入普通用户的日常操作。

### 9.2 结构与检修

后盖采用螺丝固定，支持重复拆装，检修时不应破坏外壳或键盘。关键 PCB 和连接件应具备明确的检修与更换路径；如配置电池，也应便于更换。

调试接口、连接器方向及部件标识需要便于识别。内部连接以可靠性和装配效率为先，不作为普通用户日常插拔的扩展接口。

每增加一块 PCB 或连接器，都需要验证其测试收益、装配成本和连接可靠性。首代不建立通用背板标准，也不承诺官方持续推出计算升级板。

## 10 固件更新与救援恢复

**设备即使无法启动应用固件，也应具备恢复官方系统的可靠路径。**

正常更新与救援恢复需要分别验证。用户应能够通过 USB-C 连接电脑，进入明确的更新或救援状态，写入官方固件并重新开始演奏。

霍尔键盘出厂校准数据应独立保存，并与常规固件、卡片写入范围隔离。普通更新、恢复默认设置和第三方固件刷写不得默认覆盖校准数据。

首代至少满足以下要求：

- 刷写前校验设备型号、镜像完整性及兼容信息。
- 应用固件损坏或更新中断后，仍有经过验证的救援入口。
- 刷写和恢复结果清晰可见，失败时提供可执行的下一步。
- 恢复官方系统后，键盘校准有效，官方乐器可重新使用。

Boot ROM 下载模式及具体救援入口，需要针对最终主控完成整机验证。A/B 分区属于可评估方案；存储容量和开发周期不允许时，可采用其他经过验证的恢复设计。

## 11 开放策略与官方责任

官方负责完整可靠的乐器、稳定的开发接口与清晰的恢复工具。社区可以基于同一硬件开发音源、界面、替代固件及扩展硬件。

首代在内部划分音频、按键、显示、存储和更新接口，完成基础文档。SDK、示例工程及公开资料随后完善，开放平台的完整程度不影响普通用户使用官方乐器。

| 层级 | 官方提供 | 官方维护范围 |
| --- | --- | --- |
| 官方乐器 | 官方固件、EP-1、EO-1 与稳定硬件 | 官方版本的产品质量与售后 |
| 固件开发 | 分阶段提供 SDK、HAL、接口文档与示例 | 已发布接口、文档和官方版本 |
| 第三方固件 | 刷写方式与官方恢复路径 | 工具和恢复机制，不代为维护第三方功能 |
| 扩展硬件 | 按开放范围提供引脚、电气及机械资料 | 官方接口资料，不承诺第三方设计兼容性 |
| 内部检修 | 可拆结构、检修资料及约定的备件 | 官方维修和明确公布的配件供应 |

完整替代固件与音源插件 API 分阶段推进。前者允许开发者改变整个系统；后者复用官方运行环境，降低开发单个音源的成本。

首代优先完成接口分层和可靠恢复，不冻结对外音源插件 API。插件接口需在官方乐器验证后，再确定兼容承诺与维护成本。

开放代码、驱动资料、硬件设计和音源素材分别明确发布范围。开源许可证、第三方依赖及素材分发方式在公开前确认。

## 12 首代验收

### 12.1 功能与体验验收

| 验收项 | 通过条件 |
| --- | --- |
| 独立演奏 | 断开电脑后可启动并使用已安装的官方乐器 |
| 键盘响应 | 按下与释放正确对应；连续演奏中无异常漏触发、重复触发或卡音 |
| 参数交互 | 核心参数首层可达；切换参数后转动无数值跳变；声音与显示一致 |
| 官方乐器 | EP-1、EO-1 均可完整使用，默认声音可直接演奏，声音与视觉具有清晰差异 |
| 卡片管理 | 可安装至五张并切换；第六张安装前明确提示替换；无效卡片不会进入可演奏列表 |
| 异常处理 | 卡片传输中断、固件更新中断及应用固件损坏后，可恢复到官方可用状态 |
| 数据保护 | 更新和恢复后校准数据有效；参数保存不阻塞演奏 |
| 检修 | 可拆后盖并检修关键部件；主板与键盘可分别测试，重装后功能正常 |
| 接口文档 | 音频、按键、显示和键盘通信文档与实际硬件、固件版本一致 |

### 12.2 需要冻结的量化指标

以下指标尚无已确认数值。样机阶段需确定目标、测试条件与通过标准，再进入对应的硬件或固件冻结。

| 指标 | 测量口径 | 冻结依据 |
| --- | --- | --- |
| 演奏延迟 | 从琴键达到触发条件到音频输出，覆盖典型负载与高负载 | 键盘、音频链路实测与演奏测试 |
| 启动时间 | 从开机操作到默认乐器可演奏 | 完整固件与默认资源加载实测 |
| 复音能力 | EP-1、EO-1 在约定效果状态下的可用复音 | 最终主控、内存及音源实现 |
| 卡片切换 | 从确认切换到可演奏，记录静音时间与尾音行为 | 存储、加载及资源释放实测 |
| 键盘表现 | 键程、触发重复性、力度曲线及环境变化下的稳定性 | 机械样机、传感器与校准测试 |
| 音频品质 | 约定输出条件下的噪声、失真、最大输出及爆音表现 | 最终音频电路与结构实测 |
| 便携与供电 | 尺寸、重量；若采用电池，记录约定使用条件下的续航 | 握持测试、结构与供电方案 |

以上指标需在首发验收前确定目标并完成验证，对外规格以验证结果为依据。

## 13 开发顺序
