# MDA 电钢琴：Mac 工程版

这是供 Mac 本机构建的完整工程，不是已经编译好的 .app。
本包在 Windows 上制作，没有完成 macOS 编译、界面或声卡实机验证。
共用的音源核心、按键映射、事件队列和缓冲边界已在 Windows 编译测试通过。

## 发给朋友后怎么使用

1. 在 Mac 上解压整个 ZIP，保留文件夹结构。
2. Mac 需要苹果命令行开发工具。若没有，在“终端”执行：

   xcode-select --install

   按系统提示安装完成即可，不需要安装第三方音色库、Homebrew 或完整 Xcode 应用。
3. 双击“一键构建.command”。如果不能执行，打开终端，输入 bash 和一个空格，
   把 build_macos.sh 拖入终端，再按回车。路径含空格时，拖入操作会处理路径引用。
4. 脚本先测试音源，再生成“MDA电钢琴.app”并打开。
5. 以后直接双击这个 .app。可以把生成的 .app 复制到“应用程序”目录。

如果系统阻止脚本运行，可使用上述终端方式；不要关闭系统安全设置。
构建错误请保留终端完整输出，发回继续修正。

## 功能与操作

- 纯 MDA 电钢琴，不含原声钢琴、FluidSynth、SoundFont。
- 中文界面，一排连续37键。
- 中音区：MIDI48–84；低音区：36–72；高音区：60–96。
- 白键 A S D F G H J K；黑键 W E T Y U。
- Z/X/C 切换低/中/高音区；空格延音；Esc关闭窗口；Command+Q退出。
- 点击演奏窗口后试弹。若输入法拦截按键，请切换英文输入法。
- 鼠标按住琴键演奏；鼠标本身一次控制一个音。
- 电脑键盘支持多音，但受实际键盘按键冲突限制。
- 切换音区、切换应用或窗口失焦会停止旧音，避免卡音。
- 未接入 USB MIDI 键盘、混响或合唱。

## 声音与移植方式

MDA 核心、采样和音色参数来自现有正常的 Windows 纯 MDA 版本。
Mac 端使用 Cocoa 窗口和 AudioQueue 输出：44.1kHz、双声道、16位、441帧×4缓冲。
这些缓冲数据约40毫秒；实际端到端延迟还包括设备与系统缓冲。
音频回调由系统内部线程调用，不依赖界面刷新；通过固定容量事件队列接收按键。
这份工程是 Mac 试音端，不是 F101 固件。

## 构建范围与验证限制

目标最低版本设置为 macOS 11；脚本生成当前 Mac 编译环境默认架构的应用。
Apple Silicon 和 Intel 的兼容性需要分别在对应机器构建验证，未提供通用双架构二进制。
应用使用系统 Cocoa/AudioToolbox 框架与内嵌采样，不需要随包附带第三方 DLL 或音色文件。
构建脚本会在可用时进行本地临时签名；不是 Apple Developer ID 签名，也未公证。

已验证的测试代码位于 source/test_core.cpp，内容包括：
- 事件队列满/空、FIFO和50000条跨线程事件顺序。
- 停音命令与新音符顺序。
- 37键鼠标区域、Mac物理键位映射。
- MIDI36–96逐音非静音及单音不削波。
- 441帧和可变帧数的缓冲边界、复位后静音。

macOS 本机编译、声音连续性、按钮与按键操作、默认声卡和耳机输出，仍需朋友实测。
不要把上述 Windows 的核心测试通过理解为 Mac 端已验证成功。

## 文件

一键构建.command：双击构建入口。
build_macos.sh：构建脚本；会生成 build/ 与 MDA电钢琴.app。
Info.plist：Mac应用信息。
source/main_macos.mm：Mac界面、输入和音频输出。
source/MacAudioModel.hpp：固定容量事件队列和键盘布局。
source/test_core.cpp：音源与输入逻辑测试。
其余 source 文件：原项目音源、封装、采样及其头文件。

## 模块边界与固定内存池测试（2026-10-24 增补）

| 层次 | 代码入口 | 责任 |
| --- | --- | --- |
| 音色核心 | [mdaEPiano.h](source/mdaEPiano.h)、[mdaEPiano.cpp](source/mdaEPiano.cpp) | `noteOn()` 选择键盘分区和力度层、分配固定数组中的声部；`process()` 进行 PCM 插值、循环、包络、高频塑形、声像/LFO、过载与输出。当前 Mac 编译条件下 `NVOICES=32`。 |
| 采样数据 | [mdaEPianoData.h](source/mdaEPianoData.h) | `epianoData[]` 是内嵌的只读 `int16_t` PCM，多声部共享；不是运行时加载的 WAV/SoundFont。分区、根音、起止位置、循环长度在核心构造函数的 `kgrp[]` 中维护。按数组实际 `sizeof` 为 844,836 字节。 |
| 应用音源封装 | [AudioEngineInterface.h](source/AudioEngineInterface.h)、[MdaEPianoEngine](source/MdaEPianoEngine.h) | 统一 Note On/Off、延音、参数、渲染接口。`render()` 转接到核心的 `(右, 左)` 参数顺序。封装持有混响、合唱对象，当前渲染只调用核心；两个效果仍会在构造时分配延迟线。 |
| macOS 适配 | [main_macos.mm](source/main_macos.mm)、[MacAudioModel.hpp](source/MacAudioModel.hpp) | Cocoa 界面与键鼠输入、SPSC 事件队列、AudioQueue 生命周期与回调、双声道交错输出。此处是主机输出适配，没有目标板 I2S/DMA/Codec 驱动。 |

现有调用链为：键鼠事件 → 固定事件队列 → `MacAudio::fill()` → `MdaEPianoEngine::render()` → `mdaEPiano::process()` 读取共享采样 → AudioQueue 输出。

[test_memory.sh](test_memory.sh) 构建独立的 [test_memory.cpp](source/test_memory.cpp)，不打开应用或声卡，也不修改应用的内存分配方式。按本次 16 MB 预算，使用十进制 16,000,000 字节（16 MiB 则是 16,777,216 字节）：

```sh
# 当前应用实际使用的封装，含其已构造的效果对象及延迟线
bash test_memory.sh --pool-bytes 16000000 --engine wrapper

# 只测试采样回放与 DSP 核心
./build/test_memory --pool-bytes 16000000 --engine core
```

可加 `--frames 256 --blocks 64` 指定输出块帧数和每个测试音符渲染的块数；默认是 441 帧、64 块。这里是测试负载设置，不是设备规格。脚本只构建测试程序；构建一次后可直接反复调用 `build/test_memory` 更换容量。

测试程序在初始化和运行期间把自身使用的 C++ `new/new[]` 定向到给定容量的单个内存池，包含引擎对象、内部动态数组、两路输出缓冲。容量不足直接失败，不回退到系统堆；初始化后禁止新增 C++ 分配。内存池为单调分配，销毁时统计释放的有效载荷，整轮结束后统一归还存储，适用于本次引擎的初始化分配模式。

测试覆盖 MIDI 36–96、32/70/110 三档力度、超过声部上限的触发、延音与释放、输出边界及复位静音。返回码：`0` 通过，`1` 参数或功能检查失败，`2` 容量不足或初始化后尝试分配。旧效果构造函数在中途分配失败时没有完整回收已分配数组；失败轮会丢弃整个测试池，不能把失败轮当作正常析构通过。

本机实际执行结果，适用范围为当前源码、macOS arm64、Apple clang 17、C++17 `-O2`、44.1 kHz、32 声部、默认测试负载：

| 内存项目（字节） | `core` | `wrapper` |
| --- | ---: | ---: |
| 引擎对象本身 | 2,480 | 2,944 |
| 对象及内部动态数组的有效载荷 | 2,528 | 74,508 |
| 测试输出缓冲有效载荷，含首尾保护点 | 1,772 | 1,772 |
| 内存池峰值，包含上述有效载荷、分配头与对齐填充 | 4,334 | 76,606 |
| 事件/渲染期间新增 C++ 分配尝试 | 0 | 0 |
| 正常析构后未释放的池内有效载荷 | 0 | 0 |

两种模式各渲染 5,302,584 帧并观察到 32 声部。精确容量通过、少 1 字节失败，以及其他容量、帧数和无效参数检查共 22 项通过。原有 `test_core.cpp` 在本机普通构建与 AddressSanitizer/UndefinedBehaviorSanitizer 构建下通过；macOS 应用已另行编译链接检查，未启动试音。

原始输出、编译器版本、执行条件及源码 SHA-256 见本次生成的 [build/memory_test_results.txt](build/memory_test_results.txt)。该文件是本轮结果快照，后续更改源码或参数必须重新测试，不能沿用数值。

采样没有复制进内存池；另有 41 字节共享全局变量有效载荷在池外。按采样、全局变量有效载荷与池峰值相加，本轮核心为 849,211 字节，封装为 921,483 字节，均低于 16 MB。这是已统计项目的预算合计，不是整进程 RAM 或目标板完整占用：代码、调用栈、C `malloc`（包括构造函数日志可能引发的分配）、系统分配及 Cocoa/AudioQueue 不在测试池中。当前 Mac 回调的两路临时输出共 1,764 字节位于栈上，4 个 AudioQueue PCM 缓冲有效载荷共 7,056 字节；队列元数据、驱动及系统开销另计。换目标处理器后还需在对应 ABI、链接布局与实际输出驱动下验证栈、静态区及整机资源。
